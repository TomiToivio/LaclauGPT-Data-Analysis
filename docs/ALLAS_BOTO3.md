# CSC Allas with boto3

LaclauGPT Data Analysis uses boto3's normal AWS shared configuration and credential chain for CSC Allas. Do **not** copy a CSC password, S3 access key or S3 secret key into this repository or into a LaclauGPT `.env` file merely to make boto3 work.

## CSC setup

On Roihu, configure the S3 connection with CSC's supported tooling:

```bash
module load allas
allas-conf
```

On Puhti/Mahti the equivalent S3 setup is typically:

```bash
module load allas
allas-conf -m S3
```

CSC `allas-conf` writes the project S3 key pair to `~/.aws/credentials` and the Allas endpoint to `~/.aws/config`. boto3 reads those files through its standard credential/configuration chain. The S3 credentials are long-lived until explicitly revoked, so protect the generated files with normal home-directory permissions.

For an AI26 runtime that already has `allas-conf` configured, the LaclauGPT-specific object-store configuration can therefore stay small:

```text
LACLAUGPT_OBJECT_BACKEND=s3
LACLAUGPT_S3_BUCKET=<shared-ai26-bucket>
LACLAUGPT_S3_ADDRESSING_STYLE=auto
LACLAUGPT_S3_SIGNATURE_VERSION=auto
LACLAUGPT_S3_PREFIX_ROOT=projects
```

`LACLAUGPT_S3_ENDPOINT` / `LACLAUGPT_S3_ENDPOINT_URL` and `LACLAUGPT_S3_REGION` are optional overrides. They are not needed when the active AWS profile generated by `allas-conf` already contains the endpoint. A blank region is normalized to genuinely unset rather than passed to botocore as an invalid empty DNS region.

## Allas transport defaults

When the resolved endpoint host is `a3s.fi`, the adapter automatically selects the same transport semantics CSC configures for S3 clients:

```text
addressing_style = virtual
signature_version = s3   # botocore name for S3 Signature Version 2
```

The accepted LaclauGPT signature spellings are `auto`, `s3`, `s3v2`, `v2`, `s3v4` and `v4`. `s3v2` and `v2` are mapped to botocore's actual identifier, `s3`.

For a non-Allas S3-compatible service, `auto` leaves boto3/botocore defaults in control. Explicit overrides are available when required:

```text
LACLAUGPT_S3_ADDRESSING_STYLE=auto|path|virtual
LACLAUGPT_S3_SIGNATURE_VERSION=auto|s3|s3v2|v2|s3v4|v4
```

## Preflight

`laclaugpt-preflight` now tests the capability Analysis actually needs: it uploads a tiny sentinel under the configured project namespace and immediately deletes it. This catches upload signing/addressing failures before expensive analysis/model work begins.

The sentinel is created only below:

```text
projects/<project_id>/analysis/.preflight/
```

The preflight report exposes only sanitized endpoint/provider/transport information. It never prints AWS credentials.

## Laskin or another Linux host

If `allas-conf` has already been run for the same Unix account, boto3 will use that account's `~/.aws` files directly. If configuration was created on another trusted CSC host, follow CSC guidance for securely copying the `~/.aws` configuration to the target account/home directory. Do not commit it to Git.

The project still needs an explicit bucket name because `allas-conf` selects an Allas project/credential pair, not which application bucket LaclauGPT should use.
